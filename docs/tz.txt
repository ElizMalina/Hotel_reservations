ТЕХНИЧЕСКОЕ ЗАДАНИЕ — HotelBooking
 
    1) ОПИСАНИЕ
Наименование: Система бронирования отелей «HotelBooking»

Предметная область: Гостиничный бизнес. Система предназначена для поиска, бронирования и управления номерами в отелях. Позволяет гостям находить свободные номера по датам и городу, оформлять брони, отменять их и оставлять отзывы. Администраторы управляют отелями, номерами и подтверждают брони. Менеджеры видят аналитику по загрузке и выручке.

Цель: Автоматизировать процесс бронирования номеров, исключить двойные брони на одни и те же даты, обеспечить разграничение доступа по ролям и ведение истории операций.

Назначение отзывов: Отзывы и рейтинги собираются для того, чтобы гости могли выбирать отель по рейтингу

Оплата: Все операции оплаты выполняются в транзакциях БД

Медиа в отзывах: К отзыву можно прикреплять изображения и видео

Техподдержка: Реализован приватный диалог между гостем и менеджером


2) ДАННЫЕ

Сущность: roles — Справочник ролей пользователей
   * role_id (SERIAL) — Первичный ключ, автоинкремент
   * role_name (VARCHAR(20)) — NOT NULL, UNIQUE, допустимые значения: guest, admin, manager
   Общие ограничения: Не более 3 записей (по числу ролей)

Сущность: users — Зарегистрированные пользователи системы
   * user_id (SERIAL) — Первичный ключ, автоинкремент
   * email (VARCHAR(100)) — NOT NULL, UNIQUE, формат email
   * password_hash (VARCHAR(255)) — NOT NULL, минимум 5 символов
   * full_name (VARCHAR(100)) — NOT NULL
   * phone (VARCHAR(20)) — Формат +7XXXXXXXXXX или NULL
   * role_id (INT) — NOT NULL, FK на roles, ON DELETE RESTRICT
   * created_at (TIMESTAMP) — DEFAULT NOW()
   Общие ограничения: Email уникален среди всех пользователей

Сущность: hotels — Отели системы. Средний рейтинг рассчитывается автоматически на основе отзывов и используется для сортировки и выбора отеля гостями.
   * hotel_id (SERIAL) — Первичный ключ
   * name (VARCHAR(100)) — NOT NULL
   * city (VARCHAR(50)) — NOT NULL
   * address (VARCHAR(200)) — NULL допустим
   * stars (INT) — CHECK (stars BETWEEN 1 AND 5)
   * description (TEXT) — NULL допустим
   * avg_rating (NUMERIC(3,2)) — DEFAULT NULL, обновляется триггером при изменении отзывов
   Общие ограничения: Название отеля уникально в пределах города; при сортировке по рейтингу отели без отзывов (avg_rating IS NULL) помещаются в конец

Сущность: room_types — Типы номеров внутри отеля
   * room_type_id (SERIAL) — Первичный ключ
   * hotel_id (INT) — NOT NULL, FK, ON DELETE CASCADE
   * type_name (VARCHAR(50)) — NOT NULL
   * capacity (INT) — CHECK (capacity > 0)
   * base_price (NUMERIC(10,2)) — CHECK (base_price > 0)
   * description (TEXT) — NULL допустим
   Общие ограничения: Название типа уникально в пределах отеля

Сущность: rooms — Конкретные физические номера
   * room_id (SERIAL) — Первичный ключ
   * room_type_id (INT) — NOT NULL, FK, ON DELETE CASCADE
   * room_number (VARCHAR(10)) — NOT NULL, UNIQUE вместе с room_type_id
   * floor (INT) — CHECK (floor >= 1)
   * status (VARCHAR(20)) — DEFAULT 'available', CHECK IN ('available','maintenance', 'booked')
   Общие ограничения: Номер не может быть забронирован, если status='maintenance' или status='booked'

Сущность: bookings — Бронирования номеров
   * booking_id (SERIAL) — Первичный ключ
   * user_id (INT) — NOT NULL, FK, ON DELETE RESTRICT
   * room_id (INT) — NOT NULL, FK, ON DELETE RESTRICT
   * check_in_date (DATE) — NOT NULL, не раньше текущей даты
   * check_out_date (DATE) — NOT NULL, CHECK (check_out_date > check_in_date)
   * guests_count (INT) — CHECK (guests_count > 0)
   * total_price (NUMERIC(10,2)) — NOT NULL, CHECK (total_price >= 0)
   * status (VARCHAR(20)) — DEFAULT 'pending', CHECK IN ('pending','confirmed','cancelled','completed')
   * created_at (TIMESTAMP) — DEFAULT NOW()
   Общие ограничения: Интервалы [check_in, check_out) одного номера не должны пересекаться для броней со статусом pending или confirmed

Сущность: payments — Платежи по бронированиям. Все операции выполняются в транзакциях БД для гарантии согласованности.
   * payment_id (SERIAL) — Первичный ключ, автоинкремент
   * booking_id (INT) — NOT NULL, FK на bookings(booking_id), ON DELETE CASCADE
   * amount (NUMERIC(10,2)) — CHECK (amount > 0)
   * method (VARCHAR(20)) — CHECK IN ('card','cash','online')
   * status (VARCHAR(20)) — DEFAULT 'pending', CHECK IN ('pending','paid','refunded')
   * paid_at (TIMESTAMP) — NULL, если не оплачен
   * transaction_id (VARCHAR(64)) — UNIQUE, NULL, идентификатор транзакции платёжной системы
   * refunded_at (TIMESTAMP) — NULL, заполняется при возврате
   Общие ограничения: Сумма платежей со статусом 'paid' по брони не превышает bookings.total_price; возврат возможен только для оплаченного платежа; все операции — в транзакции с блокировкой строки брони (SELECT … FOR UPDATE)

Сущность: services — Дополнительные услуги отеля
   * service_id (SERIAL) — Первичный ключ
   * name (VARCHAR(50)) — NOT NULL, UNIQUE
   * price (NUMERIC(10,2)) — CHECK (price > 0)
   Общие ограничения: Название услуги уникально

Сущность: booking_services — Связь брони и дополнительных услуг (M:N)
   * booking_id (INT) — Часть составного PK, FK, ON DELETE CASCADE
   * service_id (INT) — Часть составного PK, FK
   * quantity (INT) — DEFAULT 1, CHECK (quantity > 0)
   Общие ограничения: Пара (booking_id, service_id) уникальна

Сущность: reviews — Отзывы гостей об отелях. Используются для расчёта среднего рейтинга отеля, по которому другие пользователи выбирают отель.
   * review_id (SERIAL) — Первичный ключ, автоинкремент
   * user_id (INT) — NOT NULL, FK на users(user_id)
   * hotel_id (INT) — NOT NULL, FK на hotels(hotel_id)
   * rating (INT) — CHECK (rating BETWEEN 1 AND 5)
   * comment (TEXT) — NULL допустим
   * created_at (TIMESTAMP) — DEFAULT NOW()
   Общие ограничения: Один пользователь может оставить один отзыв на отель; средний рейтинг отеля рассчитывается как AVG(rating) по всем отзывам

Сущность: review_media — Медиафайлы (изображения и видео), прикреплённые к отзывам
   * media_id (SERIAL) — Первичный ключ
   * review_id (INT) — NOT NULL, FK, ON DELETE CASCADE
   * media_type (VARCHAR(10)) — NOT NULL, CHECK IN ('image','video')
   * file_path (VARCHAR(255)) — NOT NULL
   Общие ограничения: Не более 10 медиафайлов на отзыв; допустимые форматы: jpeg, png, webp, mp4, webm; макс. размер 50 МБ

Сущность: support_dialogs — Приватные диалоги технической поддержки между гостем и менеджером системы. Другие пользователи не видят содержимое диалога.
   * dialog_id (SERIAL) — Первичный ключ, автоинкремент
   * user_id (INT) — NOT NULL, FK на users(user_id), ON DELETE CASCADE, автор обращения (гость)
   * manager_id (INT) — NULL, FK на users(user_id), назначается при первом ответе менеджера
   * subject (VARCHAR(150)) — NOT NULL, тема обращения
   * status (VARCHAR(20)) — DEFAULT 'open', CHECK IN ('open','in_progress','closed')
   * created_at (TIMESTAMP) — DEFAULT NOW()
   * closed_at (TIMESTAMP) — NULL, заполняется при закрытии диалога
   Общие ограничения: Диалог виден только автору обращения, назначенному менеджеру и менеджерам системы; один гость может иметь несколько диалогов

Сущность: support_messages — Отдельные сообщения внутри диалога технической поддержки. Видны только участникам диалога.
   * message_id (SERIAL) — Первичный ключ, автоинкремент
   * dialog_id (INT) — NOT NULL, FK на support_dialogs(dialog_id), ON DELETE CASCADE
   * sender_id (INT) — NOT NULL, FK на users(user_id), автор сообщения (гость или менеджер)
   * body (TEXT) — NOT NULL, минимум 1 символ
   * created_at (TIMESTAMP) — DEFAULT NOW()
   * is_read (BOOLEAN) — DEFAULT FALSE, флаг прочтения получателем
   Общие ограничения: Доступ к сообщениям имеют только участники диалога (user_id, manager_id) и менеджеры системы; при закрытии диалога новые сообщения запрещены



3) ПОЛЬЗОВАТЕЛЬСКИЕ РОЛИ

Роль: Гость
   Ответственность: Поиск свободных номеров, создание брони, отмена своей брони, просмотр своих броней, оплата, оставление отзыва после выезда.
   Количество пользователей: Не ограничено (роль по умолчанию при регистрации)
   UI: Консольное меню: поиск номеров, мои брони, отмена брони, оставить отзыв. Видит только свои данные.

Роль: Администратор отеля
   Ответственность: Подтверждение и отклонение броней, управление номерами (добавление, перевод в maintenance), изменение цен типов номеров, просмотр броней по своему отелю.
   Количество пользователей: 1–3 на отель
   UI: Консольное меню: список броней, подтверждение, управление номерами и типами номеров.

Роль: Менеджер системы
   Ответственность: Управление отелями и пользователями, просмотр аналитики (загрузка отелей, выручка за период), назначение ролей.
   Количество пользователей: 1–2
   UI: Консольное меню: CRUD отелей, отчёты, управление пользователями.



4) ТЕХНОЛОГИЯ РАЗРАБОТКИ
Язык программирования: Python 3.10+
СУБД: PostgreSQL 14+
Библиотеки: psycopg2-binary (драйвер PostgreSQL), tabulate (вывод таблиц), colorama (цветной вывод), python-dotenv (конфигурация), pytest (тестирование)
Архитектура: Слоистая: UI (консольные меню) → DAO (доступ к данным) → PostgreSQL. Вспомогательный слой helpers для ввода/вывода.



5) ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ

5.1. Оплата (транзакции)
   * Все операции оплаты выполняются в транзакции с блокировкой строки брони (SELECT … FOR UPDATE)
   * Проверяется: бронь существует, принадлежит пользователю, статус pending/confirmed, сумма не превышает total_price
   * При успешной оплате создаётся запись в payments со статусом paid, paid_at = NOW()
   * При отмене оплаченной брони создаётся возврат: status=refunded, refunded_at=NOW() — в одной транзакции
   * При любой ошибке — ROLLBACK, данные не меняются

5.2. Медиа в отзывах
   * Гость может прикрепить к отзыву до 10 файлов (изображения и видео)
   * Проверяются MIME-тип и размер файла; при несоответствии — ошибка
   * При удалении отзыва медиа удаляются каскадно, файлы удаляются с диска
   * В карточке отеля отображается средний рейтинг и количество отзывов

5.3. Техподдержка (приватные диалоги)
   * Гость может создать обращение (тема + первое сообщение)
   * Сообщения видны только автору, назначенному менеджеру и менеджерам системы
   * Другие пользователи не видят диалог
   * Менеджер может отвечать и менять статус (open → in_progress → closed)

5.4. Рейтинг и сортировка отелей
   * Средний рейтинг отеля рассчитывается как AVG(rating) по всем отзывам
   * В поиске доступна сортировка по цене (возр./убыв.) по минимальной base_price
   * В поиске доступна сортировка по рейтингу (убыв./возр.)
   * Отели без отзывов отображаются с рейтингом «—» и в конце при сортировке по рейтингу



6) ТЕСТИРОВАНИЕ
Виды тестирования: Модульное (pytest) для DAO-функций, интеграционное для сценариев бронирования, ручное тестирование меню.

Сценарий: Успешное бронирование свободного номера
   Шаги: Войти как гость → выбрать отель → ввести даты 2025-07-01..2025-07-05 → выбрать номер → подтвердить.
   Ожидаемый результат: Создана запись в bookings со статусом pending, total_price рассчитан как 4 × base_price.

Сценарий: Отказ при пересечении дат
   Шаги: Попытаться забронировать тот же номер на 2025-07-03..2025-07-08.
   Ожидаемый результат: Ошибка «Номер уже занят на эти даты», запись не создаётся.

Сценарий: Запрет брони на номер в ремонте
   Шаги: Попытаться забронировать номер со status='maintenance'.
   Ожидаемый результат: Триггер БД выбрасывает исключение, бронь не создаётся.

Сценарий: Отмена брони
   Шаги: Гость отменяет свою бронь по booking_id.
   Ожидаемый результат: Статус брони становится cancelled, номер снова доступен на эти даты.

Сценарий: Разграничение доступа
   Шаги: Гость пытается отменить чужую бронь, указав чужой booking_id.
   Ожидаемый результат: Операция не выполняется (0 затронутых строк), сообщение об ошибке.
